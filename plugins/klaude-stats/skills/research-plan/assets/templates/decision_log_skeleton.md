# 操作流程與決策清單 — <專案名稱>

本檔給指導教授 / 共同作者審閱用。每個決策點都列出**採用做法、理由、影響範圍、以及要改的話改哪個檔的哪一行**。
所有數字由程式產生的 `data/*_stats.json` 讀出，未手打。

**編號與狀態**：每個決策有一個永久 ID（`A1`、`B5`、`C3`…）。**ID 一旦配出就不再重用，也不因插入新列而重排**——報告、驗收報告與投稿回覆都可能引用它。`狀態` 欄有三個值：

| 狀態 | 意思 |
|---|---|
| `active` | 現行採用的做法，報告中的數字由它產生 |
| `superseded` | 已被後來的決策取代。**該列保留不刪**，並在「採用做法」欄開頭標 `~~已取代 → 見 <新 ID>~~` |
| `withdrawn` | 曾經考慮並記錄、但最後未採用（例如老師否決）。同樣保留不刪 |

**改動決策時的流程見 H 節。** 老師或 reviewer 提出修改時走那一節，不要直接覆寫既有列。

> ⚠️ **要在表格加新欄位，一律插在「要改就改這裡」之前。** 看門狗 C2 解析的是每列的**最後一欄**，把新欄附在尾端會直接讓檢查失效。

## H. 變更控制（老師 / reviewer 提出修改時走這裡）

**為什麼需要**：這份決策清單與報告一旦交出去過，直接覆寫既有列，看過舊版的人就無法得知哪些數字變了、為什麼變；投稿回覆時也拿不出「原本怎麼做、後來為什麼改」的紀錄。

### H.1 流程（五步，不可跳）

1. **不要改既有列。** 把被取代的那列 `狀態` 改成 `superseded`，並在「採用做法」欄開頭加 `~~已取代 → 見 <新 ID>~~`。
2. **新增一列**，配一個**沒用過的新 ID**（同章節接續編號；ID 不重用、不重排）。
3. **在 H.3 補一列變更紀錄**：日期、誰要求、舊 ID → 新 ID、一句話理由、要重跑哪些腳本。
4. **從受影響的腳本往下重跑**（順序見 G 節），不要只改文字。
5. **跑看門狗**，全綠才算完成。

### H.2 什麼情況要走這個流程

| 情況 | 走 H 流程？ |
|---|---|
| 改世代定義、終點、任何門檻或切點 | **要**（且必重跑） |
| 改統計方法（模型、插補、篩選、驗證方式） | **要**（且必重跑） |
| 老師否決某個做法、要求換一種 | **要**（被否決的標 `withdrawn`，不刪） |
| 只改報告措辭、排版、章節順序 | 不用，但仍要重跑引用解析與文件組裝 |
| 修正錯字或失效路徑 | 不用 |

> **ledger 條目沒有重跑撐腰，比沒有條目更糟**——它宣稱了一個數字沒反映的改動。
