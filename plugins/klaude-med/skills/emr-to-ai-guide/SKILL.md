# emr-to-ai-guide — 把自己醫院的病歷安全接進 AI 流程

每間醫院的病歷系統（HIS）網頁結構都不同，本套件**不附**任何特定醫院的解析器。這份指南教你怎麼為**自己的醫院**做一支，並且在合規前提下使用。

> 免責：本文僅為技術流程說明，非法律或資安意見。是否可將病歷資料用於 AI，請以你所屬機構規定與主管機關法規為準，違規後果由使用者自行負責。

## 步驟 0：先確認規範（不要跳過）

動工前先查清楚，任何一項不確定就**停下來問**：
- 醫院資安／個資政策：多數醫院**禁止**把可識別病歷上傳到雲端 AI（含一般聊天機器人與 Claude 對話）。
- 你的用途是教學報告、case discussion 還是研究？研究通常需要 IRB 核准或豁免；院內教學用途也可能有各自的去識別化要求。
- 是否允許把病歷頁面存到個人電腦／隨身碟？有些院內電腦禁止存檔或安裝 Python，請改用允許的環境。
- 原則：**可識別資料不離開本機；只有去識別化後的文字才進入 AI。**若無法確定合規，就只用完全虛構的範例做練習。

## 步驟 1：在本機存下頁面

在瀏覽器開啟病歷頁，擇一方式（存到本機資料夾，例如 `~/emr-local/`，不要放雲端同步資料夾）：
1. 「另存網頁」（完整 HTML，**首選**，欄位結構最完整）
2. 「列印」→「另存為 PDF」
3. 全選複製文字，貼到本機 `.txt`

檔名不要含病人姓名或病歷號。處理完成後依院內規定刪除原始檔。

## 步驟 2：先用 `phi-deid` 在本機去識別化

使用同套件的 `phi-deid` skill（`${CLAUDE_SKILL_DIR}/../phi-deid/SKILL.md`），讓 Python 在本機把姓名、病歷號、日期等取代成代號。
- 你**不要**把原始病歷貼進對話，也不要讓 Claude 直接讀原始檔。
- 只有去識別化後的文字／摘要，才能進入下一步。

## 步驟 3：請 Claude 為你醫院的版面寫一支本機解析腳本

做法：不要給真實病歷，改給 Claude 一份**虛構或已去識別化、且只保留結構的樣本**（把內文換成假資料，HTML 標籤與欄位標題保留）。

可直接貼用的提示詞：

```
我要為自己醫院的入院病歷網頁寫一支「只在本機執行」的 Python 解析腳本。
下面是一份「虛構」的樣本 HTML（內容為假資料，結構與真實頁面相同）：
<貼上虛構樣本>

請寫 extract_note.py：
1. 用 argparse 讀入一個本機 HTML 檔路徑，用 BeautifulSoup（或標準庫 html.parser）解析，不連網。
2. 抽出這些段落：主訴、病史（現病史／過去史／家族史／用藥）、身體診察 PE、檢驗 Lab、影像報告、臆斷 Impression、治療計畫 Plan。
3. 輸出成 markdown 檔（每段一個 ## 標題），寫到我指定的輸出路徑。
4. 終端機只印「摘要」：各段落是否找到、各段字數；不得印出任何病歷內文。
5. 找不到某段時給出明確警告，不要猜測；結構改版時要容易修改（把標題關鍵字集中放在檔案開頭的 dict）。
6. 附一個用我給的虛構樣本做的簡單測試。
```

使用規則：
- 腳本寫好後，**你自己**在本機對真實檔案執行；執行輸出（markdown）請先經 `phi-deid` 檢查，再給 Claude。
- 腳本跑出來有缺漏時，只把「錯誤訊息與虛構結構片段」回報給 Claude 修，不貼真實內容。
- 每次醫院系統改版，同樣用虛構樣本重新調整。

## 步驟 4：接到簡報／書面報告

去識別化後的 markdown 可交給：
- `case-discussion-pptx`（在 `klaude-slides-docs` 包裡，需另外安裝；輸出 case discussion 投影片）
- `case-discussion-docx`（同樣在 `klaude-slides-docs` 包裡；輸出書面報告）

完成後在本機把代號還原（由 `phi-deid` 的還原步驟處理）；還原後的最終檔不要再交給 AI 讀取，也不要上傳雲端。

## 快速檢查清單
- [ ] 已確認院內規範／IRB 或教學用途許可
- [ ] 原始頁面只存在本機，檔名無個資
- [ ] 進 AI 的文字已經 `phi-deid` 去識別化
- [ ] 解析腳本是用虛構樣本開發的，執行時只印摘要
- [ ] 簡報／報告內無可識別資訊（姓名、病歷號、完整生日、罕見特徵組合）
