# 預設講義結構（9 節，可在 Stage 1 覆寫）

每堂 lecture 產出的 markdown 都遵循以下 9 節固定結構。§0-§4 由 Part A 產出；§5-§9 由 Part B 產出。最終拼接時不插分隔線，讓讀者讀起來像一整篇。

---

## 每堂起頭

```
# Lecture {NN}: <英文主題>（中文副標）

- Video: {VIDEO_URL}
- Duration: {DURATION} 分鐘
- 預計閱讀時間: XX 分鐘
```

---

## §0. TL;DR（速覽）

- **一句話總結**：這堂課解決什麼問題（≤ 40 字）
- **3-5 個 key takeaways**（條列）
- 預計閱讀時間

## §1. Motivation（為什麼要這堂課）

- 前一堂留下的開放問題（第一堂則寫整個 playlist 的 motivation）
- 產業／真實系統的具體需求
- 既有 naïve 方案的缺陷 → 為什麼需要本堂的新機制
- **至少 600 中文字**

## §2. 背景知識補完（Prerequisites）

- 本堂會用到、但讀者背景可能不熟的基礎
- 每個概念格式：`英文（中文）` + 嚴謹定義 + 白話版 + 為何本堂會用到
- 至少 4 個概念
- **至少 800 中文字**

## §3. 核心概念辭典（Core Concepts Glossary）

- 本堂**新引入**的關鍵術語
- 每個：`英文（中文）` + 嚴謹定義 + 白話重述 + 常見誤解／相近概念區辨
- 至少 6 個、最多 15 個
- **至少 1,000 中文字**

## §4. System / Paper Deep Dive

本堂核心，至少 1,500 中文字。必含：

- **4.1 Architecture**：mermaid 圖（優先）或 ASCII box；圖下文字說明每個元件
- **4.2 關鍵演算法**：偽程式碼（Python-like，註解英文）+ 中文旁白解釋「為何這樣寫」
- **4.3 關鍵 data structure**：markdown 表格
- **4.4 Walkthrough**：至少 2 組情境（正常 + 異常／故障／race condition）

## §5. 真實類比（★ 讀者背景特化）

這一節是本講義最大價值所在。**至少 3 組類比，每組 400+ 字**。

每組類比格式：
1. 類比情境描述（150+ 字）
2. 對應關係表（原系統概念 ↔ 類比場景元件）
3. ✅ 吻合之處（為何類比有效）
4. ⚠️ 不吻合之處（類比邊界，避免誤導）

類比來源依讀者 persona 決定：醫學生就類比醫院資訊系統／臨床流程；金融從業者就類比銀行系統；等等。

**至少 1,500 中文字**

## §6. 課堂 Q&A 精華

從 transcript 抽學生提問 + 教授回答。至少 6 組：

```
**Q**: 重述學生問題（繁中，可簡化）
**A**: 教授回答（中文整理 + 必要補充）
```

結尾加「**最常見誤解 Top 3**」——指出哪些問題暗示一般人容易搞錯。

## §7. 常見陷阱與考點（What Engineers Actually Get Wrong）

從 transcript、官方 notes、paper FAQ 抽出「課堂強調但 paper 沒寫、實作會踩」的坑。至少 6 條：

```
**陷阱**：...
- **為何會掉進去**：...
- **正確做法**：...
- **實例**：（可選）
```

## §8. 自測題（正好 10 題，附摺疊答案）

混合題型：
- 3-4 題概念題
- 3-4 題情境題
- 2-3 題 debug 題

每題格式：

```
N. **(類型題)** 題目文字

<details><summary>展開答案</summary>

答案要有詳細解釋，不只結論。指出「為何是這答案」、「錯在哪」。

</details>
```

- **官方 lecture notes 連結**（若有）
